# multi_agent-improver

issue-writer · issue-runner · doc-optimizer를 하나의 개선 사이클로 묶는다.
한 번 실행하면 프로젝트를 점검하고, 약점을 이슈화하고, 이슈 하나를 처리하고, 문서를 정리한 뒤 결과를 리포트한다.

## 실행 흐름

```
[1] 현황 파악     → v0 산출물 상태 점검
[2] 이슈 등록     → issue-writer   (조건: 개선 항목이 있을 때만)
[3] 이슈 처리     → issue-runner   (조건: 열린 이슈가 있을 때만)
[4] 문서 정리     → doc-optimizer
[5] 완료 리포트   → 각 단계 결과 요약
```

### [1] 현황 파악
- 핵심 파일(`orchestrator.py`, `agents/*.py`, `config.py`)을 훑고, 필요하면 `python orchestrator.py "테스트 주제"`로 동작을 확인한다.
- `gh issue list --state open`으로 현재 열린 이슈 수를 파악한다.
- 이 단계에서 "개선 항목 후보"와 "열린 이슈 유무"를 메모한다.

### [2] 이슈 등록 — 조건부
- **개선 항목 후보가 있을 때만** `issue-writer` 스킬을 따른다.
- 이미 열린 이슈와 중복되면 새로 만들지 않는다.
- 후보가 없으면 이 단계를 건너뛰고 그 사실을 리포트에 남긴다.

### [3] 이슈 처리 — 조건부
- **열린 이슈가 있을 때만** `issue-runner` 스킬을 따라 하나를 처리하고 닫는다.
- 열린 이슈가 없으면 건너뛴다.

### [4] 문서 정리
- `doc-optimizer` 스킬을 따라 SOUL·README·CLAUDE의 중복·낡음을 점검·수정한다.
- [3]에서 코드가 바뀌었다면 문서가 코드와 어긋나지 않는지 특히 확인한다.

### [5] 완료 리포트
각 단계 결과를 한눈에 요약한다:

```
## multi_agent-improver 사이클 결과
- [1] 현황: <요약 / 동작 여부 / 열린 이슈 N개>
- [2] 이슈 등록: <생성한 이슈 번호들 또는 "건너뜀(개선 항목 없음)">
- [3] 이슈 처리: <닫은 이슈 #N + 변경 요약 또는 "건너뜀(열린 이슈 없음)">
- [4] 문서 정리: <수정한 문서 또는 "변경 없음">
- 커밋: <이 사이클에서 만든 커밋 해시들>
```

## 규칙

- 조건부 단계([2],[3])는 조건이 맞지 않으면 **반드시 건너뛰고** 그 사실을 리포트에 남긴다 — 억지로 이슈를 만들지 않는다.
- 한 사이클에서 이슈는 최대 1~3개 등록, 처리는 1개만.
- 모든 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`를 붙인다.
- 변경이 있으면 사이클 종료 전에 `git push`한다.
