# issue-writer

multi_agent 프로젝트의 현재 산출물을 검토해 개선 항목을 도출하고, 각 항목을 GitHub 이슈로 등록한다.

## 1단계 — v0 산출물 검토 → 개선 항목 도출

다음을 읽고 약점/개선 여지를 찾는다:

- `orchestrator.py` — 파이프라인 조율 로직 (에러 처리, 재시도, 병렬화 여지)
- `agents/*.py` — 각 에이전트의 프롬프트 품질, 책임 분리
- `config.py`, `requirements.txt` — 설정·의존성 관리
- 실행해보고 드러나는 한계 (느린 응답, 토큰 한계, 출력 형식 등)

개선 항목은 **구체적이고 실행 가능한** 단위로 쪼갠다. 예:
- "에이전트 호출 실패 시 재시도 로직 없음"
- "research/critique 단계 결과를 사용자가 볼 수 없음 (answer만 출력)"
- "에이전트가 순차 실행 — 독립 단계 병렬화 가능"
- "테스트 코드 부재"

## 2단계 — `gh issue create` 실행

각 개선 항목마다 이슈를 생성한다. 본문은 아래 형식을 따른다:

```bash
gh issue create --title "<한 줄 요약>" --body "$(cat <<'EOF'
## 배경
이 개선이 왜 필요한지 (현재 v0의 어떤 맥락에서)

## 현상
지금 무엇이 부족하거나 잘못되어 있는지 (구체적 파일/동작 인용)

## 작업 항목
- [ ] 해야 할 일 1
- [ ] 해야 할 일 2
EOF
)"
```

## 규칙

- 이슈는 한 번에 1~3개만 등록한다 (남발 금지).
- 이미 열린 이슈와 중복되지 않는지 `gh issue list --state open`으로 먼저 확인한다.
- 제목은 명령형/요약형으로 간결하게 (예: "fix:", "feat:", "docs:" 프리픽스 권장).
- 등록 후 생성된 이슈 번호와 URL을 사용자에게 보고한다.
